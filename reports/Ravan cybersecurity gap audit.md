# Expose Ravan gaps, forge elite guardian

Ravan today is a well-intentioned passive reviewer masquerading as a full intrusion-lifecycle agent, and the masquerade collapses under inspection. Its strongest asset is genuinely rare — vendor-aware JavaScript-bundle analysis, architecture-before-severity reasoning, and a false-positive appendix discipline that commodity scanners cannot copy — but everything around that core is monolithic, unenforceable, and stateless. A single `mode: all` agent with no model pin, no steps budget, and a Unix-only deny list on a Windows-hosted project claims it "works deterministically" while OpenCode V2 offers no working temperature control to the agent author ([Source](https://v2.opencode.ai/docs/agents)). It name-drops OWASP and MITRE ATT&CK while missing the entire 2025 OWASP delta, the API Top 10, and the LLM Top 10 ([Source](https://top10.owasp.org/2025/0x00_2025-Introduction)). It ships solid DNS/TLS/header evidence yet cannot score, prioritize, or track anything across runs, using roughly two of seven V2 composition primitives while `opencode.jsonc` sits empty. The path to best-in-class is therefore not incremental polish but structural rebuild: split the monolith into a least-privilege team, pin determinism through versioning and evals rather than adjectives, teach modern frameworks and tooling literacy, add threat-intel scoring, and convert every wise prompt aspiration into file-backed memory, commands, and verification loops.

## Monolithic agent claims determinism it cannot enforce

Ravan runs as one unbounded `mode: all` agent that is simultaneously entrypoint, recon operator, code reviewer, and report writer, a shape none of the OpenCode V2 builtins use since `build` and `plan` are primary while `general` and `explore` are subagents with `general` barred from launching further children ([Source](https://v2.opencode.ai/docs/agents)). No `model`, `steps`, `color`, or `hidden` key is set, so behavior drifts silently with whatever session model the user selected, run length has no ceiling except context exhaustion, and no hidden scout-reviewer fan-out keeps noisy intermediate work out of user context. The elite contrast is explicit: V2's canonical reviewer pins a frontier reasoning model with a tight step budget and full edit and shell denial ([Source](https://v2.opencode.ai/docs/agents)), community orchestrator packs assign flagship reasoning to the orchestrator and cheaper tiers to explorers behind hidden council agents, Semgrep's 2026 platform pairs deterministic engines such as taint tracing and code slicing with frontier models to deliver **8x more true positives while cutting noise by 50%** ([Source](https://www.businesswire.com/news/home/20260319711078/en/Semgrep-Launches-Multimodal-Combining-AI-Reasoning-With-Rule-Based-Analysis-for-Detection-Triage-and-Remediation)), and Burp AI separates passive observation from active verification with per-point payload budgets and explicit dangerous-level gating ([Source](https://burp-ai-agent.six2dez.com/scanners/active)). Ravan collapses all of those roles into one prompt with a deny list plus prose as its only active-work control. The permission list compounds the failure because it is **read-mostly theater wrapped around an `ask` default**. Every report write prompts the user since `edit` is ask-everywhere despite reporting being the defining output, shell allows for `cat`, `ls`, and `grep` duplicate the already-allowed `read`, `glob`, and `grep` tools while widening shell surface for zero capability gain, and V2 matches shell resources as raw command text with no home expansion and last-match-wins ordering ([Source](https://v2.opencode.ai/docs/agents)), which leaves prefix allows such as `curl -sSI *` evadable through chaining unless the runner tokenizes strictly. The deny block lists a narrow Unix scanner set while omitting entire enumeration and credential-attack classes plus every Windows living-off-the-land vector despite the project living on `win32` PowerShell, grants `subagent * allow` even though V2 children keep their own permissions rather than a restricted copy of the parent's ([Source](https://v2.opencode.ai/docs/agents)), and pairs that with a redundant `skill * allow` that silently opts into every future installed skill. The predictable outcome is **ask-fatigue that trains approval click-through**, a failure mode V2's auto-approve flag then converts into silent allow for everything not explicitly denied ([Source](https://open-code.ai/en/docs/permissions)). Credential handling repeats the pattern of prose without enforcement since no `read` deny covers `*.env` or secret paths even though V2's own canonical example denies them ([Source](https://v2.opencode.ai/docs/permissions)). Autonomy is equally absent because the prompt contains no decomposition protocol, no background fan-out despite DNS, TLS, headers, and certificate-transparency checks being embarrassingly parallel, no plan-then-execute separation for blast-radius changes such as HSTS and CSP rollouts that V2 already supports through reserved plan actions ([Source](https://v2.opencode.ai/docs/permissions)), and no verification loop where Semgrep ships Detect to Validate to pull-request orchestration with retries and cost tracking ([Source](https://app.semgrep.dev/products/semgrep-agentic-workflows)) and Burp AI auto-queues passive findings for active confirmation ([Source](https://burp-ai-agent.six2dez.com/scanners/active)). The determinism claim is therefore the most load-bearing dishonesty in the file since identical prompts route to different model families with no model identity, prompt hash, or skill version stamped on any report, the only temperature-shaped knob is explicitly preserved-but-not-applied by the current runner ([Source](https://v2.opencode.ai/docs/agents)), and the repository's 42 offline unit tests cover scripts while **nothing evaluates the agent itself** with golden reports, severity-calibration cases, or false-positive regression prompts. The honest fix downgrades "deterministic" to evidence-first and model-dependent until a pinned reasoning-tier model, a steps budget near the documented reviewer baseline of eight, a mandatory run manifest, and an agent-level eval harness make variance auditable, the way Burp AI preserves reproducible prompt bundles with request logging and trace correlation ([Source](https://burp-ai-agent.six2dez.com/)).

## Framework illiteracy leaves modern attack surfaces undefended

Ravan advertises full intrusion lifecycle under OWASP Top 10, ASVS, Testing Guide, and MITRE ATT&CK yet carries literacy that expired around 2017. The 2021 Top 10 spans broken access control through SSRF ([Source](https://owasp.org/Top10/2021/)), but the 2025 reordering elevates security misconfiguration to second, replaces vulnerable components with the new **A03 Software Supply Chain Failures**, and adds **A10 Mishandling of Exceptional Conditions** while folding SSRF into access control ([Source](https://top10.owasp.org/2025/0x00_2025-Introduction); [Source](https://www.fastly.com/blog/new-2025-owasp-top-10-list-what-changed-what-you-need-to-know)). None of that delta exists in the prompt, so CI and build integrity plus fail-open and error-state abuse are invisible by construction. The API Security Top 10 led by broken object-level authorization, which figures in roughly **40% of API attacks** ([Source](https://owasp.org/API-Security/editions/2023/en/0x11-t10); [Source](https://salt.security/blog/owasp-api-security-top-10-explained)), is entirely absent despite APIs being the dominant 2026 surface, with no broken object, function, or property-level authorization reasoning, no mass assignment or excessive-data-exposure analysis, and no rate-limit or inventory thinking. The LLM Top 10 spanning prompt injection, sensitive disclosure, supply chain, data poisoning, improper output handling, excessive agency, system-prompt leakage, vector weaknesses, misinformation, and unbounded consumption ([Source](https://genai.owasp.org/resource/owasp-top-10-for-llm-applications-2025/)) is equally absent even though Ravan itself is an LLM agent assessing LLM-era applications. ATT&CK is decorative name-drop rather than working knowledge since Enterprise now spans **14 tactics, 216 techniques, and 475 sub-techniques** including reconnaissance, credential access, defense evasion, privilege escalation, lateral movement, exfiltration, and impact ([Source](https://attack.mitre.org/tactics/enterprise/); [Source](https://attack.mitre.org/resources/updates/updates-october-2025/)), with cloud-metadata credential access tracked as its own sub-technique reachable through SSRF against instance-metadata endpoints ([Source](https://www.elastic.co/docs/reference/security/prebuilt-rules/rules/cross-platform/credential_access_web_server_cloud_imds_ssrf_request)), yet no finding carries tactic or technique tags and no planned next step maps to follow-on techniques an authorized operator should test. The twelve-class web list of SQLi, NoSQLi, command injection, three XSS flavors, CSRF, SSRF, IDOR, deserialization, auth, upload, traversal, and business logic has zero prompt literacy for the classes PortSwigger treats as first-class in 2026 ([Source](https://portswigger.net/web-security)), namely JWT algorithm confusion and header-injection attacks ([Source](https://portswigger.net/web-security/jwt)), multi-parameter OAuth combination analysis ([Source](https://portswigger.net/web-security/oauth)), GraphQL introspection and nested-query abuse plus WebSocket and race-condition predict-probe-prove methodology ([Source](https://portswigger.net/web-security/race-conditions)), and the JWT, OAuth-flow, and GraphQL abuse vectors now described as leading API exploitation paths ([Source](https://hivesecurity.gitlab.io/blog/api-security-jwt-oauth-graphql-attacks)), alongside SSTI, XXE, prototype pollution, request smuggling, cache poisoning, cloud-metadata-to-Kubernetes chains through AWS IMDS, GCP metadata headers, Azure IMDS, and pod service-account tokens ([Source](https://www.appsecure.security/blog/ssrf-cloud-environments); [Source](https://hacktricks.wiki/en/pentesting-web/ssrf-server-side-request-forgery/cloud-ssrf.html); [Source](https://www.resecurity.com/blog/article/ssrf-to-aws-metadata-exposure-how-attackers-steal-cloud-credentials)). Methodology is five words of lifecycle plus a Rules-of-Engagement fragment where PTES demands seven phases from pre-engagement through threat modeling, vulnerability analysis, exploitation, post-exploitation, and reporting ([Source](https://kirkpatrickprice.com/blog/stages-of-penetration-testing-according-to-ptes)), pre-engagement must fix scope, windows, forbidden techniques, contacts, data handling, and authorization with nothing outside scope without fresh approval ([Source](https://deepstrike.io/blog/penetration-testing-methodology); [Source](https://blog.securelayer7.net/penetration-testing-rules-of-engagement)), and design-phase practice combines STRIDE per trust boundary with attack trees for depth and risk-matrix prioritization ([Source](https://strobes.co/blog/threat-modeling-explained-stride); [Source](https://cheatsheetseries.owasp.org/cheatsheets/Threat_Modeling_Cheat_Sheet.html); [Source](https://threat-modeling.com/pasta-threat-modeling)), a need OWASP itself elevates by insisting insecure design cannot be fixed by perfect implementation ([Source](https://owasp.org/Top10/2021/A04_2021-Insecure_Design/index.html)). Best-in-class 2026 agents already run planner-executor or swarm architectures with ReAct tool-chaining around explicit methodologies rather than single-shot scans ([Source](https://appsecsanta.com/research/ai-pentesting-agents-2026); [Source](https://matproof.com/blog/ai-penetration-testing-guide); [Source](https://www.synack.com/learning-center/what-is-ai-penetration-testing-complete-guide)), including single-outcome simulated-attack agents with safety controls against lateral movement ([Source](https://xbow.com/blog/what-is-ai-pentesting)). Payload reasoning without weaponizing is the right instinct executed as one content-free sentence about detection strings and header checks, while elite practice pairs Nuclei's engine-plus-YAML-template model with tag, severity, and workflow selection ([Source](https://tech-insider.org/nuclei-vulnerability-scanner-setup-2026); [Source](https://github.com/projectdiscovery/nuclei-templates); [Source](https://www.bugcrowd.com/blog/the-ultimate-beginners-guide-to-nuclei)) and understands that Nuclei needs a live host list and complements rather than replaces manual Burp and ZAP deep dives plus pre-deploy SAST and infrastructure scanning ([Source](https://trickest.com/tools/nuclei); [Source](https://tech-insider.org/nuclei-vulnerability-scanner-setup-2026)). Tooling literacy names six tools in one line and deny-lists their execution, which for a planning agent is precisely backwards since its value is drafting authorized commands and reading output, yet standard 2026 layering spans Nuclei, OpenVAS, Burp, ZAP, Semgrep, and Checkov with scheduled automation ([Source](https://tech-insider.org/nuclei-vulnerability-scanner-setup-2026)), Semgrep pairs rules with AI reasoning for detection, triage, and remediation ([Source](https://semgrep.dev)), and cloud, Kubernetes, and Active Directory review demand BloodHound, Prowler, Cloudsplaining, and cluster RBAC tooling ([Source](https://appsecco.com/product-security-testing/cloud-k8s-iam)). The rebuild that earns the framework claims is an edition-pinned mapping table with CWE crosswalks, a dedicated API-security section and LLM-application annex, mandatory ATT&CK tactic-plus-technique tagging on findings and next steps, per-class planning blocks with safe verification observables and Burp and ZAP workflow pointers, a threat-model section with assets, boundaries, and one or two crown-jewel attack trees preceding findings, a validation-backlog appendix per gated claim, and a tiered guardrail ladder from description through inert detection to authorized-operator drafts with human sign-off explicitly required for compliance audiences.

## Passive recon impresses yet fails to score and prioritize

Credit where brutal honesty demands it: architecture-before-severity, exploitable-versus-gated verdicts, vendor-chunk classification with per-result method recording, public-by-design key labelling, wildcard suppression, method-refusal discipline, and SOA and NSEC trap handling constitute unusually strong false-positive machinery for this class. The audit still finds that every mechanism carries documented residual weakness that reports must surface as explicit uncertainty rather than silent confidence. Certificate-transparency enumeration through keyless `crt.sh` wildcard queries yields subdomains without touching the target ([Source](https://www.cybersec-lounge.com/passive-recon-crt-sh); [Source](https://hackindex.io/services/web/reconnaissance/certificate-transparency-enumeration)), a source Subfinder enables by default with no API key ([Source](https://deepwiki.com/projectdiscovery/subfinder/3.3.2-certificate-transparency-sources)), yet Ravan enumerates from a fixed twelve-name wordlist with resolution checks and no CT, passive-DNS, or search-engine source. WHOIS and RDAP context is standard passive tradecraft ([Source](https://reconshield.in/blog/anatomy-of-passive-osint); [Source](https://tryhackme.com/room/passiverecon)) yet no registrant, nameserver, or registration-date facts are collected at all. Email security is the weakest pillar relative to business impact since full grading spans SPF, DKIM, DMARC, MTA-STS policy content, TLS-RPT, DANE, BIMI, rDNS, STARTTLS, and blocklists with weighted scoring ([Source](https://github.com/aloki-alok/mailgrade); [Source](https://swissarmytechtools.com/email-security-analyzer/)), correct rollout requires **testing mode plus monitoring for two or more weeks before enforce** with non-wildcard MX patterns ([Source](https://www.security.gov.uk/policy-and-guidance/set-up-tls-rpt-and-mta-sts/)), and reference assessors grade testing-mode, MX-mismatch, and short-duration policies distinctly ([Source](https://github.com/danielmichaels/gecko/commit/38cd6d7ac3f55662df8b4ca214bddb7566611a0b)), while Ravan checks only DNS TXT presence, never fetches the policy file, never validates mode or MX or age, and never checks BIMI, DANE, lookup-count limits, key sizes, redundancy, or STARTTLS — so toothless transport security looks identical to hardened. DNSSEC is presence-only with no chain validation, CSP analysis flags dangerous tokens without numeric quality scoring or enforcement weighting while SRI is a boolean without per-resource coverage, header consistency diffs only extra paths against root for a narrow set without error-page policy comparison, source-map detection covers only the first fourteen assets and ends on a dangling inline-mapping comment, and TLS assessment negotiates default plus legacy probes with no cipher enumeration, no preload-list membership, no signed-certificate-timestamp verification, and no revocation signal. Numeric posture scoring is absent even though Mozilla Observatory demonstrates the model of baseline-minus-penalties-plus-bonuses with grades from A+ down to F ([Source](https://developer.mozilla.org/en-US/observatory/docs/tests_and_scoring)) across individually tested headers, HSTS, redirection, and cookies ([Source](https://developer.mozilla.org/en-US/observatory)), which leaves regression tracking and board trending impossible. Evidence capture through verbatim copy-pasteable observations plus machine-readable JSON and request logs is a solid base, but severity remains analyst mood because findings carry **no CVSS vector, no EPSS percentile, no KEV membership, and no confidence label**. EPSS publishes daily thirty-day exploitation probability with percentile free via API ([Source](https://www.first.org/epss/)), FIRST publishes explicit guidance on combining it with CVSS and KEV ([Source](https://www.first.org/epss/)), industry practice increasingly chains all three as a patch-prioritization decision tree ([Source](https://arxiv.org/html/2506.01220v3)), EPSS v4 scores even backlog items lacking CVSS ([Source](https://www.decryptiondigest.com/blog/epss-vulnerability-prioritization-patching-workflow-guide)), and non-federal organizations increasingly use KEV alongside CVSS supplemental metrics ([Source](https://www.defendermate.com/dmate-blog/cvss-vs-epss-vs-ssvc-vs-kev)). Without that overlay a medium-severity KEV-listed item ranks below a high-severity never-exploited item, which is exactly the inversion the chaining exists to prevent. Report structure already matches roughly **80% of OWASP and PTES best practice** with scope, methodology, limitations, executive summary, findings table, details, done-well, roadmap, verification, and appendices, where standards demand dual-audience writing with business-context strategy for executives and full technical proof for engineers ([Source](https://wstg.owasp.org/latest/5-Reporting/01-Reporting_Structure/); [Source](https://pentest-standard.readthedocs.io/en/latest/reporting.html)) and insist the executive summary stay to one or two jargon-free pages answering what was tested, headline risk, business impact, top actions, and cost ([Source](https://www.hedgehogsecurity.co.uk/blog/what-a-good-penetration-test-report-looks-like); [Source](https://www.hackthebox.com/blog/penetration-testing-reports-template-and-guide)). The missing three structural additions carry the highest value: an attack-chain narrative showing how spoofing plus form abuse plus framing combine into one business compromise since its absence is called the most-missed highest-value section ([Source](https://www.hedgehogsecurity.co.uk/blog/what-a-good-penetration-test-report-looks-like)), implementation-ready remediation grouped by horizon with dependencies and effort ([Source](https://www.hedgehogsecurity.co.uk/blog/what-a-good-penetration-test-report-looks-like); [Source](https://www.cycognito.com/learn/penetration-testing/penetration-testing-report/)), and disclosure operational detail beyond a single ninety-day mention even though that window traces to Project Zero's ninety-day deadline ([Source](https://projectzero.google/vulnerability-disclosure-policy.html); [Source](https://en.wikipedia.org/wiki/Coordinated_vulnerability_disclosure)) with ZDI and federal policies using sixty-to-ninety-day variants ([Source](https://www.zerodayinitiative.com/advisories/disclosure_policy/); [Source](https://www.commerce.gov/vulnerability-disclosure-policy); [Source](https://www.hhs.gov/vulnerability-disclosure-policy/index.html)) while AI-assisted weaponization arguments claim ninety days is already too slow ([Source](https://www.tomshardware.com/tech-industry/cyber-security/standard-90-day-vulnerability-disclosure-policy-is-likely-dead-thanks-to-ai-leaving-worlds-systems-exposed-to-zero-day-attacks-security-expert-details-how-llm-assisted-bug-hunting-ushers-in-a-new-cyberworld-orders)). Residual false-positive risks concentrate exactly where the tool already warns honestly: single-bundle signature-only verdicts across minifier families, medium and low-confidence version fingerprints feeding advisory correlation, bounded DKIM sweeps presented as inference, legacy-TLS inconclusive states, an inconsistent Stripe publishable-key classification that invites critical-leak over-rating, and acknowledged CMS under-reporting with no passive plugin enumeration path. The fix adds three fields per finding for CVSS, EPSS plus KEV, and confidence with reason, enriches every dependency verdict through keyless feeds, mandates a coverage matrix per class in limitations, and schedules bundle-replay validation per release so bundler drift cannot silently reintroduce the traps the project worked hardest to kill.

## Stateless one-shot wastes every run while cheap power sits unused

Ravan executes a single authorized scan into JSON plus Markdown and then forgets everything, which squanders the highest-leverage work in security operations: tracking, suppressing, retesting, and watching. Custom commands are single Markdown files whose filenames become slash commands with prompted placeholders and inline shell interpolation ([Source](https://opencode.ai/docs/commands)), MCP servers configure locally via launched processes or remotely via URL with project-over-global override ([Source](https://composio.dev/content/mcp-with-opencode); [Source](https://opencode.ai/docs/config)), the GitHub server supports toolset limiting because unscoped use floods context ([Source](https://github.com/github/github-mcp-server/blob/main/docs/installation-guides/install-opencode.md)), subagents run in fresh-context child sessions under the parent's launch permission ([Source](https://opencode.ai/v2/docs/agents)), and project guidance loads automatically from `AGENTS.md` plus instruction-listed files ([Source](https://opencode.ai/docs/rules); [Source](https://opencode.ai/v2/docs/instructions)). Ravan uses almost none of this, so every engagement starts from freeform prose instead of pinned invocations, advisory correlation stays bolted on with an offline fallback instead of infrastructural, and conventions such as output directories, contact identity, and request budgets are renegotiated each session. Semgrep ships a local MCP server with security check, scan, custom-rule scan, syntax-tree, findings, language, and schema operations backed by **more than 5000 rules** ([Source](https://github.com/semgrep/mcp)), with Guardian bundling server, hooks, and skills into scan-on-generate loops ([Source](https://semgrep.dev/products/semgrep-guardian)), which is the highest-leverage single add because it converts code review from grep-opinion into deterministic SAST without data leaving the machine. The concrete rebuild maps each workflow to one cheap artifact rather than one more paragraph of prompt advice. Guided intake becomes an assess command driving a fixed question flow for target, ownership proof, scope boundaries, stack, data sensitivity, and contact before any scan starts, Rules-of-Engagement generation becomes a sign-off-required document rather than a sentence fragment, and retesting becomes a finding-ID-scoped command that re-runs only covering checks and marks outcomes as fixed, persisting, or regressed against machine-diffable JSON facts that the skill already emits by design. Scheduled sweeps belong outside OpenCode on OS cron invoking headless runs until a native scheduled-session primitive is confirmed, dependency watching becomes a stdlib script batch-querying the keyless OSV API for up to one hundred dependencies per call across aggregated GHSA, PyPI, Go, RustSec, NVD, and Debian sources ([Source](https://www.firecrawl.dev/alexandria/osv-dev); [Source](https://github.com/google/osv.dev)), and baseline-then-diff between timestamped report runs becomes the highest-value reporting upgrade for repeat engagements since no single database is complete and the union of NVD, OSV, and GHSA materially exceeds any one source ([Source](https://safeguard.sh/resources/blog/open-source-vulnerability-database-comparison)). Memory follows the same file-backed pattern that OpenCode already loads for free: an append-only finding ledger powering dedup and diffs, a suppressions file recording rejected positives with evidence hashes so future sessions skip re-flagging without re-reasoning, and a per-target profile capturing architecture class, impossibility statements, accepted risks, and severity overrides with a diffable audit trail, extended by golden before-and-after report fixtures plus adversarial false-positive fixtures in CI. Integration priority stays ruthlessly read-only and keyless first with local caching: KEV membership plus EPSS probability enrichment as the biggest severity-signal upgrade per line of code ([Source](https://www.cisa.gov/resources-tools/resources/kev-catalog); [Source](https://www.decryptiondigest.com/blog/cisa-kev-automated-alerts-guide); [Source](https://docs.invicti.com/appsec/cisakev-epss-integration)), OSV batch queries with per-record source attribution since advisories publish in OSV format ([Source](https://docs.github.com/code-security/security-advisories/working-with-global-security-advisories-from-the-github-advisory-database/about-the-github-advisory-database); [Source](https://github.com/github/advisory-database)), keyless certificate-transparency context with wildcard-DNS caveats ([Source](https://dev.to/0012303/crtsh-has-a-free-api-find-every-ssl-certificate-for-any-domain-with-python-2nlk); [Source](https://www.subdomainsfinder.com/crtsh-alternative)), local Semgrep SAST, read-scoped advisory access, read-only Nuclei template metadata for interpreting operator-provided output while execution stays denied, and key-gated exposure feeds documented as optionals rather than core. Hard-won wise behaviors around architecture-first verdicts, exploitable-versus-gated labelling, exact-directive remediation with failure modes, email-auth sequencing, limitations honesty, done-well credibility, and legal steering toward practice labs only become reliable when encoded as a fill-in report template with per-section checklists, a reproducible severity rubric citing its reason per finding, and a remediation library promoted into loaded instructions with rollback for every dangerous rollout.

| Build priority | What ships | Why it wins |
|---|---|---|
| Harden the agent team | Split orchestrator plus hidden recon, reviewer, and reporter subagents with pinned models, step budgets, deny-by-default permissions, and plan-mode separation | Ends monolith drift, privilege laundering, ask-fatigue, and blast-radius execution in one move |
| Score every finding | Add CVSS, KEV, EPSS, and confidence fields with cached keyless enrichment and architecture-aware rubric | Converts opinion-ranked lists into defensible patch order executives fund |
| Remember everything | Ship ledger, suppressions, target profile, baseline diff, retest command, and golden evals | Turns one-shot scans into compounding coverage with auditable severity history |
| Teach modern surfaces | Add OWASP 2025, API, and LLM annexes with ATT&CK tagging, threat models, attack trees, and safe verification catalog | Closes the JWT, OAuth, GraphQL, race, cloud-chain, and supply-chain blindness competitors exploit |
| Wire cheap power | Add assess, threat-model, harden, retest, and RoE commands with Semgrep-local and advisory-read MCP | Captures most of best-in-class capability as Markdown and JSON before any exotic engineering |

## Conclusion

The merciless version is that Ravan's reputation currently rests on prompt adjectives and script tests while determinism, authorization, scoring, memory, and methodology rest on nothing enforceable. The wise version is that the project already owns the two hardest differentiators — evidence honesty and false-positive humility — and every gap above maps to a small versioned file rather than a research breakthrough. Build the team, the ledger, the rubric, and the verification loops first, and Ravan stops being a clever scan wrapper and starts becoming the guardian its name promises.
